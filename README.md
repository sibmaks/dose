# Dose — Android medication reminder

Android application ID and Kotlin package: `io.github.sibmaks.app.dose`. Changing from the earlier `com.example.dose` ID installs a separate app; Android does not transfer that app's private medication data automatically.

Native Android adaptation of the Dose HTML/Vue prototype. Kotlin, Jetpack Compose and Material 3, AlarmManager, notifications, and on-device SharedPreferences/JSON. No account or server is needed at runtime.

## Build and run

Install JDK 21, Android SDK API 35, and a compatible Android Studio. Open this folder and let Gradle sync, then run the app on Android 8.0+ (API 26+).

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

The APK is `app/build/outputs/apk/debug/app-debug.apk`. The bundled Gradle wrapper downloads its pinned distribution on first use. The project uses Gradle 9.8.1, AGP 9.1.1 with built-in Kotlin, and the Kotlin Compose plugin 2.2.10.

## Features

- Shared launcher/header icon: the header loads the same adaptive icon resource as the Android launcher.
- English, Russian, Belarusian, Armenian, Azerbaijani, Kazakh, Kyrgyz, Romanian, Tajik, Turkmen, Uzbek, Ukrainian, and Georgian interface translations. The globe button opens a full language page styled like medication entry, with bundled SVG country flags; first launch offers a choice while defaulting to the system language. Android 13+ also exposes the same languages under Settings → Apps → Dose → Language. Older Android versions use the in-app picker.
- Today dashboard, upcoming/overdue doses, completion indicator, and seven-day local history. Swipe horizontally between Today, Medications, and History, or tap the matching bottom navigation item.
- Add, edit, pause, and delete medications without removing previous dose history. Add/edit uses a guided sequence: name and color → form → amount and unit → schedules → optional instructions and final review. Other opens an additional optional custom-form text step. Back preserves entries and drafts survive rotation. When editing, Save is available on every step (in the header before the final step); it validates the entire draft and opens the first invalid step with inline errors. Delete medication is on the name step, immediately above Continue.
- Name suggestions use the editable `app/src/main/dictionary/medication-dictionary.json` with stable English codes, localized name lists, form lists, and aliases, plus previously saved names. Gradle packages a generated gzip asset; the app loads it off the UI thread and uses a word-prefix index for offline lookup. Display follows the app language with English fallback; the expanded catalog includes translations for all 13 app languages. All localized name variants of matching medicines are selectable, with exact matches first and no default result cap. Saved copies replace only the same spelling of the same medicine; selecting a name keeps that spelling and preselects an editable form. Matching uses words/prefixes, so calcium no longer matches inside colecalciferol. Calcium, alfacalcidol, and explicit thyroxine spelling aliases are included. Free name input remains available. Catalog scope and primary references are in `docs/medication-dictionary.md`.
- Medication forms: pill, capsule, liquid, spray, drops, injection, cream, and Other with a custom label. SVG source illustrations live in `design-reference/medication-forms`; Android vector drawables use the same paths in the editor, dashboard, medication list, and notification small icon.
- Separate dose amount and unit, with mg, ml, g, mcg, IU, tablet, capsule, drop, spray, and puff presets plus an editable custom unit. New medications preselect tablet for pills, capsule for capsules, ml for liquids/injections, spray for sprays, drop for drops, and g for creams. Other requires choosing a unit. The default follows form changes (including name suggestions) until the user types a unit or selects a preset; existing saved units are preserved.
- Multiple schedules per medication. Each rule has one or several times and can use specific dates, selected weekdays, selected month days, or every day.
- Each schedule can use the default dose amount or its own amount via **Set a different amount**, below **Add time**. The unit is shared by the medication. Today, notifications, pop-ups, the widget, and recorded history use the amount for that occurrence.
- Six preset colors (including rose and amber) plus a touch color wheel with brightness and hex controls. Tap any swatch to select that saved/preset color directly. Only Pick a custom color opens the wheel; drag to adjust hue/saturation, then confirm Use color. Cancelling leaves the medication’s current color unchanged. Up to eight swatches appear, with frequently saved colors first and the current selection included. Usage persists across app restarts; pausing does not increase usage.
- Feed notifications use Android's standard layout and action styling with only Taken and Skip, including deferred reminders. They show the dosage, scheduled time, and instructions; grouped reminders list each medicine and apply either action to the displayed group. Taken records the actual click time. After Snooze or Later, the pop-up also offers On Time (original scheduled acceptance time) beside Taken. Today’s pending dose cards offer only Taken and Skip; tap a card to change the reminder or acceptance time. History labels On Time records and preserves the actual click separately.
- Optional pop-up reminder window over other apps, with Taken, Snooze, Skip, and Later actions. Enable it from the bell setup and grant Android's Display over other apps access. The pop-up uses purple pill-shaped actions, side-by-side Snooze and Skip controls, medication cards, and scheduled-time badges.
- Pop-ups vibrate with two short pulses when a new reminder appears. Redrawing the window does not repeat vibration; device alarm/vibration settings still apply.
- History includes a Time to take report: average delay overall and per medication, with 7-day, 30-day, and all-time views. Each Taken entry also shows its acceptance time and delay; On Time entries are labelled.
- Reminders restored on reboot, clock/time-zone changes, package upgrades, and exact-alarm permission grants.

## Languages

The app uses Android string resources for screens, medication form labels, editor errors, accessibility descriptions, notification actions/channels, and pop-up controls. Dates and report numbers use the selected locale. The language picker shows each language in its own script and includes **System language** to clear an explicit selection. Unsupported system languages fall back to English for app text. Language changes recreate the activity while preserving saved editor drafts. User-entered names, notes, custom forms/units, and stored schedule keys are not translated.

Android 13+ uses the framework `LocaleManager` and `res/xml/locales_config.xml`, keeping the picker and Android app-language settings synchronized. Android 8–12 store the choice locally and wrap activity/background reminder contexts. Visible pop-ups refresh when the language changes without vibrating again. Existing notification text is not rewritten; new reminders use the current language. All languages are included in app bundles so switching works offline after installation.

Translations have resource/format validation but have not been reviewed by native speakers. The medication-name JSON supports every app language, with English fallback for missing translations. The starter data retains English/Russian names; free input accepts names in any language.

## Schedule behavior

- Start and end dates are optional and inclusive for recurring rules. An empty start is anchored to the day the rule was created, rather than advancing each day. Clearing an explicit start in the editor anchors it to today. An empty end continues until paused or deleted.
- Specific-date rules can contain several dates and stop after the last one. Each rule's times apply to all of its selected dates.
- Month days are actual calendar dates: a rule for the 31st skips months without a 31st; it does not move the dose to the last day of the month.
- Overlapping rules for the same medication, date, and time produce one dose, log, and notification. Equal amounts merge automatically. When different amounts overlap, Save asks which schedule takes priority, highest first, until every conflict is resolved. The choice is saved and applies only at overlapping occurrences; other occurrences remain. Calendar checks include specific dates, weekdays, month days, and inclusive bounds. Changing an amount or schedule clears the old priority order so Save can ask again. Duplicate times within one rule are rejected; different medicines may share a time.
- Alarms find the next unrecorded matching date for each medication/time. Recording Taken or Skip completes only that slot and advances its alarm; snoozes are stored separately.
- Times follow the device's local time zone. Daylight-saving gaps and overlaps use Java's `ZonedDateTime` resolution (gaps move forward, overlaps use the earlier offset).
- Existing daily medications migrate automatically to a daily rule. Recognizable dosage text such as `500 mg` splits into amount and unit; other text is preserved. IDs, colors, instructions, pause state, and dose history remain intact.

## Today-only changes

Tap a medication card in Today’s schedule to change its reminder to another future time today, or use **Taken at** to record/correct acceptance at a chosen time that has already passed today. The detail screen shows the form with its colored icon, dosage, status, scheduled time, snoozed or recorded time, instructions, and all schedules. Tap the time to choose a different value; there is no On Time shortcut on this screen. **Edit medication** opens the full editing flow and returns to the dose details after saving/cancelling if that dose still exists. Reminder changes apply only to that dose and date; other doses and recurring rules stay unchanged. A moved dose retains its original identity for Taken/Skip/Undo and uses its changed deadline in the report. Snoozing changes delivery time but keeps that deadline. Enabled instructions require text before Save.

## Home-screen widget

Add **Dose · Today** from the Android launcher’s widget picker. It shows the earliest pending dose for today, its reminder time, medication form, and dosage. A due/overdue dose stays visible until resolved. Snoozes and today-only changes are reflected; completed/empty days show no pending dose. Tap it to open Today. It refreshes on dose actions, scheduled time transitions, midnight, clock/time-zone changes, reboot, and language changes, with Android’s periodic widget updates as a fallback.

## Delay report

Delay is the time from the original scheduled deadline to the recorded acceptance time. Taken uses the actual click time; On Time explicitly uses the original scheduled instant, even after snoozing, and contributes zero delay. The original click timestamp is also retained. Early clicks contribute zero delay; skipped and unrecorded doses are excluded. The average is weighted by taken doses, not by medication. Reporting periods use the scheduled date, including doses taken after midnight. Snoozing does not move the report baseline.

New records persist their scheduled instant so later time-zone changes do not reinterpret that timestamp. Older records remain readable; their deadline is estimated from the stored date and time in the current time zone and the report labels these estimates. Renamed or deleted medications retain their historical report entries.

## Notification pause

The bell’s settings include **Pause all notifications**, until a selected future date and time. Both the feed and overlay (including vibration) are suppressed, and currently visible reminders close. The deadline survives restart and reboot; reminders resume automatically or with **Resume notifications now**. Doses remain pending and visible in Today/the widget. Resuming schedules future reminders without sending a burst for doses missed during the pause. Permission choices and recurring medication schedules are retained. Later is hidden when the chosen reminder setup is already complete.

## Permissions and reliability

- First launch offers a full reminder setup page after language selection. It explains notification and display-over-app permissions, plus Android’s additional exact-alarm access where needed. Later dismisses the offer without requesting access, and it does not repeat on every launch. The reminder setup banner is the first item in Today whenever setup is incomplete. The bell reopens the same full page. Feed and Pop-up switches request their missing Android access directly. Each switch stays off until its own permission and exact-alarm access are granted; denial cancels that enable attempt. Returning from settings rechecks actual access. There is no second setup page. Choices persist; turning both styles off keeps schedules saved but disables reminder alerts.
- The bell stays gray until choices have been reviewed, exact alarms are available, and each chosen style has its required access. It turns purple when ready. A deliberate feed-only choice does not require overlay access. Returning from Android settings or a permission prompt refreshes the bell and setup status.
- Android 13+: turning on Feed requests notification permission. If previously denied, setup opens app settings. It also checks the Medication reminders channel, so a blocked channel is not reported as ready.
- Android 12+: grant Alarms & reminders access when requested by either reminder switch for precise timing. Without it, Android may delay alarms.
- Pop-ups are off by default. Turn on **Bell → Pop-up over other apps**, grant **Display over other apps**, and allow exact alarms when requested. Exact alarms allow the foreground pop-up service to start while Dose is closed. If Android blocks the service, the ordinary dose notification remains available when the feed is enabled and permitted.
- With feed notifications off, pop-ups still work when permitted, but there is no dose notification to return to after they close. Android may still display the temporary foreground-service notification while a pop-up is visible.
- The pop-up runs for at most two minutes, then closes without recording or skipping doses. Several simultaneous reminders share one scrollable window. Later keeps dose notifications when the feed is enabled; Taken and Skip use the same recording behavior as notifications, while Snooze remains available in the pop-up. Permission revocation, pause/delete/schedule changes, and dose actions remove invalid pop-ups.
- Pop-ups do not unlock or wake the phone. Android or protected apps can suppress overlays; lock-screen reminders continue to use notifications. The Sound & notification settings button opens Android's channel controls for sound and Pop on screen where supported.
- Vendor battery policies, force-stop, power off, and Do Not Disturb can interfere with alerts. A force-stopped app receives alarms again after launch.
- Snoozes apply to the current day's dose. This app does not provide clinical advice or track inventory.
